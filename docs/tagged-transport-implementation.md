# TAG 辅助换货实现

入口位于现有船货／路线面板上方。默认关闭；关闭时保留原有自动规划路径。开启后，自動規劃沿用已选策略、议价力预算和主界面的搜索模式。普通规划器提供经过 TAG 规则完整回放的单船参考；TAG 状态搜索在相同时间预算内优化独立背包、码头转货和切号。旧的单船极限求解协议本身不具备角色库存语义，不能把多个容器简单合并后交给它计算。

## 操作

1. 打开「TAG 辅助换货 → 设置」，输入主号、小号的实际最大 LT、日常占用 LT、可用格数。两角色均有笛子，不需要填写小象所在地 ID。船最大 LT 和日常载重仍取原船舶设置。有效参数在离开字段或关闭窗口时自动保存，启动时自动加载，无效输入不会覆盖上次有效设置。
2. 设置出发安排和载货限制；搜索模式及自定义时长统一在主界面选择。空载新规划默认从首个装货仓库开始；勾选「从此处出发」才计入前往该仓库的航段。已有初始携货或重算执行中的路线，保留真实位置。航速与操作耗时不再用于方案排名，也不在设置窗口展示。初始携货只填写已经离开仓库的真实货物。
3. 码头表分别列明人物装卸和仓库连接。Kuit、Lema 作为有公开操作证据的中转点；尚只有 NPC 存在证据的候选默认关闭，玩家核实后可以启用。未伪造 Ancado 在 Sausan 的仓库连接。当前目录尚未覆盖全部欧服港口。
4. 按原来的自动规划按钮。步骤包括仓库存取、人物与船转货、切角色、当地小象转货／仓库叠货及交换；转货列出来源、目的地、商品和数量，每步附船／两角色 LT；普通航行行和累计时间不展示。地图绘制剩余访问顺序，详细操作在路线面板执行。
5. 按「完成下一步」推进。允许撤回最后一次勾选；这只是修改软件中的执行记录，不会撤销游戏操作。「重算剩余路线」继承实际位置、各背包和仓库快照。
6. 最后卸货也必须完成，然后按「结算仓库与交换」写入仓库和 Planner 完成记录。独立修改过的冲突库存不会被覆盖；同值结算可以重试。已结算路线不能再撤回勾选。

## 路线查看与界面

- 完成交换并回到有仓库的港口后，下次装货／出航开始新路线；首次前往仓库装货的空船航段不单独算一趟。普通岛屿码头的切号与转货仍属于同一趟。分组只影响展示，不改变搜索结果、货物状态和执行顺序。
- 单船保底调用普通规划器生成可串联多个岛屿的路线，并尝试保留当前已有的普通路线。候选必须按 TAG 的实际出发点、货物数量、港口权限和格数完整重放，确认可执行后才参与总距离比较；禁止直接套用过时任务或虚构仓库连接。搜索未找到更短方案时保留单船方案，界面显示其路线条数及总距离。
- 显示路线总数与当前执行路线，可选择全部或单条路线；地图线条、文字、装卸港口标记使用相同的显示计划和筛选状态。文字复用普通模式的 RouteStepLabelPlanner 与地图渲染流程，保持步骤身份和实际交换数量。点击航段可定位到对应步骤，卡片选择会高亮对应航段；路线引导开关与普通模式共享。
- TAG 作为显示覆盖层保留原来的普通路线和选择状态，启用时不再强制切换手动模式。关闭后恢复普通路线显示。地图双击 TAG 交换只能完成当前可执行步骤，不会绕过之前的装卸动作或调用普通模式的库存完成流程。搜索期间禁止推进、撤回和结算执行进度。
- 交换卡片沿用原路线的主题、选中边框、岛屿名、双方物品图标与数量。左键双击复制换入货物的原始名称，右键双击复制换出货物的原始名称，复用原 Planner 行解析。
- 设置与路线面板使用局部主题样式，跟随软件深浅色；设置保留出发安排与载货限制，取消独立搜索秒数输入。表格编辑保持原来的自动保存及无效输入保护。
- 完成一个可见操作时，一并回放此前隐藏的航行段；撤回恢复到上一个可见操作的状态。内部航段仍用于地图、总距离和库存位置验证，不需要单独点击完成。
- 同一路线、同一地点连续的仓库装卸动作合并为一张清单，每项列图标、数量和来源／目的容器；其中的切号、召唤、叠货仍按原顺序显示。途中无仓库参与的倒货保留独立操作。完成／撤回按合并卡片处理，旧存档停在清单中途时保留已完成明细。
- 路线摘要明确区分使用 TAG 小号、仅用主号辅助及单船保底；启用开关不代表搜索结果必然使用角色载货。

## 模型与距离优先

- 六类独立存放位置：船、主号、小号、各自小象、各地仓库。每个角色和坐骑有 LT／格数；两个角色均可用笛子召唤自己的小象。到新转货地点后，路线明确列出所属角色的召唤步骤，并计算其耗时；不会凭空移动或复制小象上的货物。
- 每次普通转移都验证来源、活动角色、地点能力、数量、接收前负重和接收后格数。角色之间不能直接交换，码头不能无条件访问仓库。
- 主动装船不超过正常船容量；交换前也要求正常船载重。交换后容许比例和人物接货前比例独立配置，默认 170%，清楚标为需要按 EU 实测校准的操作假设。不能把它们理解为已逐项证实的官方统一上限。
- 仓库直接取到人物采用正常 LT 限制；船／小象转到人物按一次一叠处理，不可叠货物逐件接收。物品等级 6／7 当前按不可叠处理。
- 仓库小象叠货是受地点和活动角色限制的准备动作，按批次估算往返时间。没有将每个 UI 点击展开成单独行；该工作流来源于用户已确认的游戏实践。
- 航道距离沿用 ShippingCorridorGraph；现有坐标按游戏厘米转为米。码头接近位置当前采用岛屿导航点，加独立靠港时间，所以耗时是估算，不能声称精确到秒。
- 搜索优先比较整套路线的总航行距离，等距时比较路线条数，再比较操作数。速度和切号耗时不参与优先队列、状态淘汰、剪枝或最终方案选择。可以为接货而先切号，也可以选择回仓解除接收冲突。未找到完整合法序列不发布。
- 普通规划的可执行结果作为距离保底，再搜索利用角色、小象载货串联更多岛屿的方案。界面展示总距离及相对单船参考缩短的距离。
- 有限搜索不宣称全域最优。大任务集仍保留可行基线，不能为了缩短距离丢弃选择的交换。旧时间字段仅为兼容存档回放保留。
- Custom 接收主界面的完整截止时间，围绕完整航次进行合并、任务迁移、顺序和装载策略调整；普通模式的分批数量不限制 TAG 数量重组。Extreme 保留无改进收敛条件，Custom 不采用该条件。「停止并保留结果」发布经过完整回放验证的当前最佳方案；无可行结果时保留原路线。
- x86 主搜索最多保留 50,000 个完整候选指纹和 12 个可行方案，不再依赖反复清空逐操作状态队列来延长搜索。每个状态只复制实际发生变化的容器，未变库存只读共享。分支隔离回归检查父状态和其他分支的库存、剩余交换次数及步骤不被修改。

## 保存与恢复

新增 `Resources/tagged-transport-settings.json` 和 `tagged-transport-session.json`，相对于应用实际运行目录。使用独立文件保留旧路线存档；写入有临时文件和备份，恢复会回放验证动作与载重／时间快照。

旧版固定小象地点存档会先校验原始指纹，再转换到笛子模型：补充必要的召唤步骤、重算耗时，并映射已完成步骤数。原有货物数量和结算基线保持一致；无需重新输入旧库存。

设置、码头、船、初始库存、交换内容和时间参数都进入指纹。搜索期间外部输入改变时拒绝发布旧结果。执行中不能用一份新的空背包计划覆盖实际进度；重算保留最初结算基线，防止仓库扣加重复。新设置不静默改变已保存路线的参数。

## 验证

- 路线回归套件含新机制测试；覆盖独立装载规则、码头权限、切角、叠货、不可叠商品、笛子召唤与所属角色、慢航、完整任务保留、存档迁移与篡改检测、设置保存加载、剩余重算及结算基线。
- WPF 独立冒烟工具：`Tools/TaggedTransportUiSmoke`。在其自己的输出目录生成模拟设置和存档，不修改实际应用运行目录的用户数据；验证 350 像素路线面板、设置窗口、完成步骤、重启恢复、撤回和关闭开关，并生成图片。
- 向冒烟工具传入实际 TAG 存档路径会只读加载该存档及岛屿目录，在隔离输出中验证地图所有路线和逐条路线切换、完成交换、撤回及普通模式恢复。`--search <存档路径> 600` 对真实任务执行完整十分钟 Custom 搜索，并验证耗时、自动装货起点、单船距离保底及全部操作回放；结果写在冒烟工具输出目录。
- 源码／回放测试和离屏 WPF 验证不能替代 EU 游戏实测。实际负重门槛、完整港口菜单、码头接近时间仍按研究文档记录的证据边界处理。
