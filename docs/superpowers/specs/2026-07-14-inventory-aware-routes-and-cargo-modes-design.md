# 库存感知航线与船舱模式统一设计

## 背景

当前自动航线已经能够把 Planner 的交换结果拆成多条可执行路线，但还存在四类体验和正确性问题：

1. 路线只在“当前船上能够交换什么”之间贪心选择，没有主动利用另一仓库已有的中间产物。因此即使贝尔利亚已有 `800216`，仍可能先去生产它，再回头访问途中岛屿。
2. Planner 手动加载保存数据后会让船舱进入手动模式，却没有继续恢复与当前输入完全匹配的已保存自动航线。
3. 手动添加交换后，自动航线仍保存在内存里，但下拉框被禁用，无法直接切回；手动项目又使用旧模板，缺少图标、负重变化和可读的深色主题样式。
4. 地图只对交换岛使用较弱的字体加粗，仓库停靠点不参与高亮，实际不容易辨认当前路线。

## 目标行为

### 1. 仓库库存可以打破交换依赖

- 规划器把所有仓库中的现有物品视为可立即使用的真实库存。
- 如果贝尔利亚已有某个后续交换需要的中间物品，路线可以先到贝尔利亚装货并完成该交换，不必等本轮先生产该物品。
- 后续交换重新获得同类物品时，卸货规划仍优先送回原先保存该物品的仓库，形成“先用库存，稍后补回”的闭环。
- 大规模规划不再只接受第一条贪心可行解。贪心解作为基线，同时运行有上限的库存感知 Beam Search；搜索即使达到上限，也保留已经找到并通过校验的最佳完整解。

### 2. 长路线进行安全的局部重排

- 现有精确局部搜索在步骤较多时容易在达到完整深度前耗尽移动预算，因此需要增加确定性的单步骤迁移优化。
- 每个候选顺序都必须完整重放装货、交换和卸货状态；只有库存、负重和仓库约束全部满足，并且目标函数严格变好时才接受。
- 不为圣殿海岸侦查地等具体岛屿写死规则。正确顺序由仓库库存、依赖、航行距离和负重共同产生。

### 3. Planner 加载后自动恢复路线

- Planner 每次成功加载保存数据后，都用当前 Planner、仓库、船舶负重和地图输入生成指纹，并尝试恢复 `Resources/automatic-route-plan.json`。
- 只有指纹完全一致且路线重新校验通过时才恢复；否则继续保留手动模式，避免显示过期路线。
- 程序启动和用户点击“加载”共用同一条恢复路径，避免启动能恢复、手动加载不能恢复的分叉逻辑。

### 4. 手动模式与自动模式可以无损切换

- 鼠标中键手动添加岛屿时，仅切换当前船舱显示模式，不删除已生成的自动路线。
- 只要仍保留有效自动路线，下拉框始终可用。用户选择某条路线或“全部”时，立即切回自动路线模式。
- Planner 内容、仓库库存、TotalLT 等真实输入发生变化时，仍按现有规则使旧路线失效。

### 5. 手动交换使用与自动路线相同的卡片

- 手动添加的交换卡片使用与自动交换步骤相同的深色卡片、物品图标、岛名和交换数量显示。
- 手动顺序没有明确仓库停靠点，因此不伪造装货/卸货卡片；但会计算该顺序能够成立所需的最小初始货物。
- 第一次重放用于求每种输入物品的缺口；第二次从最小初始货物开始重放，计算每一步完成后的 LT 和累计峰值。
- 拖放排序、双击复制等原有交互继续作用于对应的原始 `Barter` 对象。

### 6. 地图明显标识当前路线

- 当前路线的交换岛与仓库岛都进入统一的高亮集合。
- 单条路线使用更粗、更大的文字和清晰的边框/背景强调；物品等级原有颜色仍保留。
- 手动模式也高亮当前手动交换岛。
- “全部”仍然只是总览展示，不改变船舱执行状态或规划结果。

## 正确性约束

任何自动路线都必须满足：

- 每一步 `TotalWithExtraLT <= TotalLT`；
- 船上任何物品数量不得为负；
- 仓库任何物品数量不得为负；
- 交换输出最终卸回该物品已有归属的仓库，无法匹配时才使用既有兜底规则；
- 保存路线只有在输入指纹一致且校验器通过时才能恢复；
- 进入手动显示模式不会使自动路线失效，只有真实规划输入变化才会失效。

## 测试策略

- 为库存感知场景建立大于 12 个任务的规划测试，验证仓库中间物品能在生产步骤之前被使用，并在之后补回。
- 为长路线建立超过旧局部搜索深度预算的重排测试，验证明显绕路能够在保持可执行性的前提下缩短。
- 为手动负重投影建立纯逻辑测试，覆盖正常依赖、消费者早于生产者和 ExtraLT/峰值。
- 为路线快照测试交换岛与仓库岛的统一高亮集合。
- 为 Planner 恢复、下拉切换和手动卡片绑定增加源代码守卫测试，并执行全部规划测试、地图测试和应用构建。
