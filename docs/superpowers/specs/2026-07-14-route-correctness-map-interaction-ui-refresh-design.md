# 自动路线正确性、地图交互与界面焕新设计

## 目标与范围

本轮在不改变 Planner 交换选择语义和仓库库存真相的前提下，完成三组相互衔接的改进：

1. 修正大任务量路线排序、补充货源模式的可行解搜索，以及 Planner 与船舱路线的原子保存和启动恢复。
2. 统一岛屿、物品和界面中文；中文使用台服游戏术语，但所有字形和界面措辞显示为简体中文。
3. 增加船舱步骤与地图路线联动、自动路线岛屿强调、仓库停靠点，并用 Microsoft Fluent UI System Icons 重做工具栏视觉。

不改手动物品交换数据、仓库数量和船舶载重规则；`ALL` 仍只用于路线总览。

## 已确认的根因

### 路线顺序

当前航行走廊本身能正确区分右上区域内部直连和经过 Halmad 的进出路线。以用户报告的顺序为例：

- `Iliya → Hakoven → Lema → Arehaza → Iliya` 的走廊距离约为 6,574,757。
- `Iliya → Hakoven → Arehaza → Lema → Iliya` 的走廊距离约为 3,908,474。

后者短约 40.6%，且载重与交换依赖允许该顺序。问题位于大任务量启发式流程：初始贪心会优先执行刚被解锁的交换链，之后全局共享的局部移动预算可能在较早路线耗尽，不能保证每条路线都获得重排机会。

### 补充货源模式与保存

当 Planner 选出超过精确搜索阈值的任务时，当前代码只依赖单一路径的贪心 incumbent；贪心走入死路后即返回“达到搜索限制前尚未找到可行路线”，没有有界的多候选回退搜索。

Planner 目前在船舱路线求解前就应用并保存新的交换倍率。若后续求解失败，Planner 文件已经改变，而 `automatic-route-plan.json` 仍是上一份成功路线；启动时两者指纹不同，因此恢复必然被拒绝。

### 中文名称

仓库步骤经过本地化资源，但交换步骤直接把内部 `IslandId` 拼入标题，所以显示英文。当前语言枚举和资源文件仍以 `TraditionalChinese/zh-TW` 命名，界面词条混有繁体字；岛屿和物品目录实际已经大量使用简体字形，造成来源和展示规则不一致。

### 地图状态

地图加粗逻辑只读取手动船舱的 `CargoDetails`，自动路线步骤不会参与。地图节点也只来源于 Planner 交换和固定临时岛屿，纯仓库停靠点（例如 Velia）没有独立节点。路线线段共用同一个无类型 Tag，无法定位并突出某一条到达线段。

## 路线算法

### 大任务量可行解

保留 12 个及以下任务的精确搜索。超过阈值时按以下顺序求解：

1. 运行现有确定性贪心，快速取得候选。
2. 若贪心无解，运行有界 beam search。每层扩展可交换任务、仓库装货和可结束路线动作；按路线数、已完成任务数、走廊距离、载重余量和稳定键排序，并按状态键去重。
3. 搜索状态数严格受 `MaxExpandedStates` 限制；找到的计划必须由 `RoutePlanVerifier` 完整回放。

beam search 的目标首先是找到可行解，不声称全局最优；UI 状态继续显示 `BestKnownWithinLimit`。

### 单路线动作排序

新增依赖感知的单路线排序器，输入为既有路线的装货动作和交换任务集合：

- 装货、交换均作为动作；只有 `RouteStateTransition` 接受的动作才能扩展。
- 对动作数较小的路线使用子集动态规划；较大路线使用有界 beam search。
- 完成全部动作后调用 `WarehouseUnloadPlanner` 重新生成卸货顺序。
- 每条路线获得独立预算，不能被前面路线耗尽。
- 只有整份计划路线数不增加、总距离严格下降且验证通过时才接受替换。

这一阶段明确覆盖“初始装入 Arehaza 输入，同时 Hakoven 输出解锁 Lema”的交错依赖场景。

## 原子规划与持久化

Planner 自动规划改为候选事务：

1. 在不可变快照上计算候选倍率，不立刻修改 WPF 行。
2. 使用候选倍率构造船舱路线请求并求解。
3. 只有路线状态为 `Optimal` 或 `BestKnownWithinLimit` 且验证成功，才一次性应用倍率、刷新库存变化、发布船舱路线并保存两者。
4. 求解失败时保留原 Planner 倍率、原自动路线、当前路线选择和地图状态。

自动路线与 Planner、StorageManager 的数据保持一致，保存到程序运行目录的 `Resources/automatic-route-plan.json`。持久化指纹加入明确的路由算法版本；版本变化时旧路线不恢复。恢复失败写入具体诊断：文件缺失、指纹不同、反序列化失败或回放失败。

## 中文名称策略

- 中文语言选项对用户显示为“简体中文”，保留原数值 `1`，兼容已有设置。
- UI 词条全部改为简体中文表达，例如“窗口、计划、保存、加载、图标、贡献度、乌鸦硬币优先”。
- 游戏实体名称采用现有台服术语表并统一为简体字形，例如 `Velia → 贝尔利亚村庄`。
- `AutomaticRouteCoordinator` 提供统一的岛屿显示名解析；仓库和交换步骤都通过它生成标题。
- 物品步骤继续从全局物品目录读取 `ItemNameDisplay`，禁止退回 ItemID；缺失时显示本地化的“未知物品”。
- 用户已修改的 `Resources/Islands.zh-TW.csv` 内容保留，不覆盖“贝尔利亚村庄”。

## 船舱与地图联动

### 步骤选择

协调器保存 `FocusedRouteNumber` 和 `FocusedStepIndex`。单击自动路线交换卡片时：

- 地图突出从上一个实际停靠点到该交换岛的到达线段。
- 线段先进行一次约 600ms 的粗细/透明度脉冲，再保持较粗、高对比颜色。
- 若系统关闭客户端动画，则不播放脉冲，只保持高亮。
- 装货或卸货卡片也可聚焦其到达线段；本轮默认允许所有自动步骤使用同一交互。

### 路线岛屿强调

- 选中具体路线时，加粗该路线所有交换岛名称。
- `ALL` 模式加粗所有可见路线的交换岛；船舱步骤仍保留最后选中的具体路线。
- 手动模式继续以 `CargoDetails` 决定加粗。

### 仓库节点

地图节点模型从“必须有 Barter”拆分为岛屿视觉节点：交换、仓库和临时位置标记是不同角色。

- 当前可见自动路线包含装货或卸货步骤时，确保对应仓库岛存在节点。
- 仓库节点使用 Fluent 仓库/货箱图标和琥珀色强调；标签合并同岛操作，例如“贝尔利亚村庄 · 装货/卸货”。
- 节点使用 `GetDisplayCenterNormalized`、现有缩放逻辑与 `AdjustLabels`，Velia 不再依赖注释 XAML 坐标块。
- 路线切换后移除不再需要的纯仓库节点，不影响 Planner 交换节点。

## 界面视觉系统

### 图标来源与接入

从 Microsoft `fluentui-system-icons` 官方仓库选取 regular/filled SVG，仅保留本程序实际使用的图标，并转换为 WPF `Geometry` 资源。仓库为 MIT 许可，项目内保留来源与许可说明。

图标映射：

- 新建：Document Add
- 保存：Save
- 加载：Folder Open
- 刷新：Arrow Sync
- 清理：Broom / Delete
- 完成：Checkmark Circle
- Planner 自动规划：Route / Vehicle Ship
- 扫描：Scan
- 加入：Add Square
- 地图仓库：Box / Building Bank
- 地图定位：Location

### 视觉方向

主题为“航海仪表台”，重点是清晰而不是装饰：

- 深海背景 `#0B1F2A`
- 面板背景 `#122D3A`
- 海图青交互色 `#32B8C6`
- 仓库琥珀色 `#E5A84B`
- 主文字 `#EAF4F7`
- 次文字 `#8FAAB4`

新建通用 Fluent 工具栏按钮样式：图标从当前前景色继承；悬停时使用半透明青色背景并改变图标颜色；按下时轻微缩放；禁用时降低透明度；键盘焦点有清晰描边。颜色通过动态主题资源提供，深浅主题分别覆盖，不在每个按钮中写死。

Planner、扫描器和船舱工具栏统一间距、圆角和图标尺寸。移除船舱中的旧“自动/最优路线”按钮；自动规划入口只保留在 Planner。保留清空船舱等仍有独立意义的操作。

## 测试与验收

1. 路线回归：上述四岛场景必须选择 `Hakoven → Arehaza → Lema`，并验证距离严格更短。
2. 大任务回归：构造超过 12 个任务、单贪心会死路但 beam search 可完成的请求，结果必须可回放且不超重。
3. 事务回归：候选路线失败时 Planner 倍率、当前计划和持久化文件均不变化；成功时一起更新。
4. 恢复回归：同指纹恢复成功；算法版本、Planner、仓库或容量变化时给出明确拒绝原因。
5. 本地化回归：交换步骤岛名、仓库名、物品名和关键 UI 词条均不含内部英文 ID；中文资源不得包含已列出的繁体界面词。
6. 地图状态回归：路线切换产生正确的粗体岛集合；聚焦步骤映射到正确路线编号和入站线段；仓库步骤产生仓库节点。
7. XAML/编译：所有 Fluent Geometry 可加载，工具栏无旧 PNG 图标引用，项目编译通过。
8. 人工检查：在深色和浅色主题下检查悬停、按下、禁用、键盘焦点，以及 300px 船舱宽度下的卡片布局。
