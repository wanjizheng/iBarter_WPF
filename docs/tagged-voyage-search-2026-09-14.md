# 普通／TAG 搜索修正与验收

## 搜索目标与载重边界

两种模式均优先比较整套路线的总航行距离，然后比较路线条数，再比较装卸／操作。TAG 不以预计耗时排序。普通模式继续由原有 `RouteStateTransition` 验证船的正常载重上限；TAG 由 `TaggedTransportSimulator` 验证船、主号、小号、小象、各仓库的独立库存和码头权限。

普通路线只是 TAG 的一个可行起点，不限定 TAG 的航次、岛屿分组或交换数量分批。TAG 搜索会合并航次、移动交换、调整顺序、重新选择卸货仓库，并重新合并因普通船重限制而拆开的交换数量。交换后允许的超载和是否允许超载航行分别服从 TAG 设置；没有把人物／小象的容量简单加到船上。

## 实现

- `TaggedVoyageSearch` 对完整路线做合并、顺序反转、单点插入、跨路线迁移、路线交换、数量重组、最终卸货仓库变更。后续搜索从少量不同可行方案继续进行多步调整和重新分组，允许保留略长的中间方案以寻找后续改进。
- `TaggedVoyageCompiler` 计算一整趟需要的货物，按顺序依赖扣除沿途得到的输入；安排出发仓库的船／人物／小象预装，并枚举已启用的真实码头进行腾位、补货。分别尝试人物与小象的分配顺序、正常航行和用户允许的交换后超载策略。
- 每个候选保留未修改的前缀，重新计算受影响的航次，再连续回放后缀。所有切号、召唤、叠货、装卸和交换最终都经过同一个模拟器；未完成全部交换或未卸下所有重货的结果不能替换当前方案。
- 接收空间不足时必须先腾位；不能把人物背包上的输入当作船上输入。不存在仓库的码头不能访问仓库，关闭的码头不能转货。人物之间不能直接转移。
- 主搜索保存完整方案级候选的紧凑指纹；指纹包含种子操作历史、受影响航次、交换顺序／数量、目的仓库和装载策略。最多保留 50,000 个指纹，按 FIFO 淘汰；最多保留 12 个不同的可行备选。不会因逐操作状态表达到上限而从头重启主搜索。
- 只有在尚无可行起点时才使用旧逐操作搜索建立初始解，例如起始货物已经在人物身上、或普通模式本来就无法执行该交换。得到完整解后转入整航次搜索。
- Custom 使用一个共同截止时间，停止时保留已验证的最佳结果；Extreme 另外保留无改进收敛条件。搜索计数界面改为「搜尋候選」，不把完整航次候选称作单个库存状态。
- TAG 重新规划会回放并保留同条件下已有 TAG 方案；设置变化导致旧操作不合法时丢弃该候选。回放重新计算载重、距离和货物，不信任旧的汇总数字。
- 普通模式补充按航行距离优先的路线成对重建候选，保留原有负重释放策略，新增内层截止时间／取消检查。Quick、Balanced、Deep 现在也接收并验证已有较好方案，避免重新搜索丢失较优结果；原有 Extreme／Custom x64 求解路径保留。
- 切换搜索模式改变计算预算时，原持久化指纹格式保持不变；先确认除搜索预算外的输入完全一致，再按新请求完整回放，才允许继续利用已有方案。船重、任务或库存变化不会被误当成预算变化。

## 回归检查

新增测试覆盖：

1. 单船需要两趟、人物预装＋中途无仓库码头倒货后只需一趟，并达到该简单几何场景的距离下界。
2. 关闭中途码头、填满人物及小象容量后，不能虚构货物空间或继续使用倒货捷径。
3. 普通模式拒绝超过正常船重的交换输出；TAG 在设置允许时接受交换后超载并合法驶回仓库，关闭超载航行后拒绝该方案。
4. TAG 合并普通模式因输出负重而拆开的同一项交换数量。
5. 没有任何普通可行起点时，TAG 仍可找到自己的可行方案。
6. TAG 重新搜索保留旧的较短可行方案；码头关闭后拒绝旧方案。
7. Quick／Balanced／Deep 的新搜索不覆盖同输入下已验证的更短方案。
8. 原有设置保存、执行进度、地图路线分组、双击、停止、仓库结算和普通路线恢复检查继续执行。

## 验证边界

这是有预算的启发式搜索，不提供大规模问题的全局最短证明。航次货物编排仍采用有限种装载策略，并非枚举所有搬货顺序；当前重建器要求该新航次的初始净输入在出发仓库可取，跨仓库取货主要通过已有合法前后缀及分趟组合保留，可能漏掉更复杂的跨仓库补货方案。运行满时间、完整回放合法和发现更好的路线分别验证不同性质。

普通模式已有方案被保留，不意味着每次从零开始的限时搜索都能得到完全相同结果。实际 EU 的负重门槛和码头功能仍由原研究文档及用户设置限定；源码／模拟器验证不能代替游戏内执行。
